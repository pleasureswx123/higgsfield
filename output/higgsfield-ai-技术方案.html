TECHNICAL ARCHITECTURE

AI 图片与视频制作平台
技术方案

双前端、统一业务后端、独立异步执行。以项目管理创作，以不可变快照保证可追溯，以公司 NAS 保存长期资产。

higgsfield-ai整理日期：2026-10-28依据：架构方案 v1.14 及当前补充条款

01架构结论与边界

首期采用模块化单体 + 独立 API / Worker 进程。制作端与管理端共享同一套领域服务和数据库事务，在控制工程复杂度的同时，将长时间模型调用、媒体处理与普通请求隔离；后续按实际负载拆分和扩容。

创作主线

先用生图模型制作图片，选定图片后交给视频模型生成视频。元素是可选的多图复用容器，直接使用图片也能完成链路。

事实与资产归属

PostgreSQL 保存项目、任务、权限与费用事实；NAS 保存长期媒体；Redis 承担队列通知、缓存与短期限流。

消费安全

生成前校验授权、能力与预算；调用后保留受理证据、用量和结果。提交结果未知时先核查，防止重复消费。

方案覆盖：项目、素材与版本、元素多图及 @ 引用、图片/视频生成、协作、供应商治理、费用预算及 NAS 归档。

本文介绍平台的目标架构、核心技术链路与设计约束；具体实现进度和运行状态以实际交付记录为准。

03端到端生成链路

STEP 1准备图片

上传或生图，选择需要的结果并归档；可直接引用，也可加入角色、场景或道具元素。

STEP 2固定输入

选项目、目录、模型及参数，固定图片版本、元素修订和引用角色；@ 操作只编辑草稿。

STEP 3受理与执行

校验授权和预算，原子写入快照及事件；后台准备素材，调用模型并跟踪结果。

STEP 4归档与复用

结果下载到 NAS，校验后授权预览；用量结算独立推进，作品可再次转为素材。

  1. 服务端重新校验：身份、项目状态、对象使用权、模型已发布能力、路由与价格有效性；不能信任前端可选项。
  2. 原子受理：同一 PostgreSQL 事务内预占全部适用预算、创建任务不可变快照并写入 Outbox。任务固定发起目录，后续切换页面不改变结果归属。
  3. 异步调度：Outbox 投递任务 ID，Worker 从数据库读取上下文；外部提交前再次核验授权与项目消费状态。
  4. 供应商执行：适配器将平台素材转为已验证的上传、注册或临时传输形式；同步图片响应直接记录输出，异步视频取得上游任务 ID 后查询，不混用两种协议。
  5. 输出落地：先建立输出记录，再归档并关联可用文件；归档、用量与费用分别推进。生成成功但归档失败时只补偿归档。

任务状态通过平台 SSE 与数据库快照恢复。浏览器刷新、关闭或网络断开不终止后台任务；平台状态 SSE 不依赖供应商支持流式生成。

04领域模型与数据约束

领域核心建模关键不变量
项目与授权项目、成员、项目角色、目录、用户偏好任务与成本必属项目；隐藏、置顶和目录移动不改变权限。
媒体与元素文件 → 素材版本 → 元素修订；元素可含多图历史文件与修订不可覆盖；可编辑业务别名不替代永久 ID。
创作与作品草稿、任务快照、引用、供应商调用、输出槽位编辑草稿不改变已受理输入；固定引用角色，不误合并首尾帧。
供应商治理连接、账号、凭据版本、能力版本、路由、上游素材绑定业务项目与上游账号分离；绑定受账号、区域、注册策略等作用域限制。
费用与可靠性价格版本、用量证据、预算预占、账本、Outbox、审计计费去重；差额追加调整；事件和历史证据不能以业务删除覆盖。

数据库统一为 PostgreSQL，业务表使用 hf_ 前缀、小写下划线及 bigserial 主键；平台业务 ID 经 API 传为十进制字符串。沿用 create_by/create_time/update_by/update_time；可删除业务对象使用 del_flag=0/2，不可变账本与审计不开放删除。

无物理外键：依靠 Service 事务、锁、引用校验和数据库联合唯一约束维护逻辑关联。这要求覆盖并发写入、删除、恢复及跨项目复制测试。迁移必须真实执行，所有表和字段保留中文注释。

金额采用 PostgreSQL numeric 与 Python Decimal；金额带币种，跨币种不得直接相加。时间按 UTC 保存，报表默认以 Asia/Shanghai 展示，供应商账期保留独立口径。

05异步执行与故障恢复

采用可靠投递 + 消费去重 + 阶段状态控制，不把消息队列或分布式锁等同于外部收费调用“恰好一次”。生成、归档、费用、用量及内容审核分别记录状态。

故障 / 并发场景设计处理
重复点击或请求重放按用户、项目和幂等键建立唯一约束；同键同请求返回原任务，同键不同摘要返回业务冲突。
数据库已提交但未入队调度器扫描 Outbox 重投；Redis 丢失后由数据库未完成任务与到期时间重建通知。
重复消息 / Worker 重启事件去重、状态版本比较、阶段租约及 fencing token；拒绝过期执行者写回。
提交超时 / 响应丢失进入 submission_unknown，依据上游任务 ID、受理查询或人工核查恢复；无证据不得直接重发生成。
同步图片结果未持久化即崩溃若供应商不能查询或安全重放，保留未知和来源不可恢复证据，人工处理，不承诺自动找回。
查询失败 / 临时结果过期查询有界退避；若可用则刷新原任务结果，否则人工处理，不能以重新生成掩盖归档丢失。
NAS 不可用阻断新上传、限制新生成，优先归档在途结果；禁止写入断挂后的本地同名空目录。
取消或撤权未提交任务阻止消费；已提交任务继续查询、归档与计费。取消不等于上游已停止，也不等于免费。

所有自动重试设置次数上限、截止时间和下次执行时间，超出后进入可审计的人工处理流程。已有上游任务 ID 时只查询原任务；租约过期不能直接触发再次收费提交。

06供应商与凭据治理

模型目录、网关调用别名、底层模型名称、精确版本、能力配置及价格分别建模。发布后的模型参数来自已验证契约，不能依据截图或报价表自行开放 4K、Fast、音频或高级运镜。

  • 统一适配：适配器承担参数映射、媒体上传/注册、同步与异步响应归一、错误分类和用量提取。供应商无法直接读取 NAS 或公司内网 URL。
  • 凭据集中治理：管理端配置 API Key，密文保存、版本化和脱敏展示；采用经审查的认证加密方案，例如 AES-GCM，主密钥通过部署秘密注入并与数据库备份分离。
  • 路由可重现：项目运行时固定经授权的供应商、账号、凭据及配置修订；不能在失败时透明切换到不相关账号。
  • 安全轮换：新任务使用新凭据，在途任务保留原绑定。VideoPlus 按当前契约使用创建时原 Key 查询；同账号新 Key 不能未经验证替代。
  • 启用门槛：连接安全、账号作用域、输入限制、结果保留期、幂等/取消语义和用量证据验证后才发布相关组合。

07费用与预算一致性

区分平台计价、供应商采购成本、供应商账单结算三个口径；价格由后台手动维护并版本化发布，调用保留价格、汇率、能力及路由快照，历史可重算和解释。

阶段一致性措施
受理前估算依据已发布价格与模型规格计算预估和所需预占。未知价格不是免费；预算周期、估算上界等策略需在启用前明确。
受理事务锁定并原子校验全部适用预算，预占、任务与 Outbox 同事务提交，避免并发超额受理。
执行后结算保留原始用量证据并归一；按上游计费身份去重，累计 usage 重复返回不能重复扣费。
不确定费用缺失用量标记 unknown 或 partial；失败、取消、提交未知均不能直接记零或盲目释放预占。
对账与修正账单导入去重；无法唯一匹配的记录进入差异队列。保留原账本，追加调整，不以采购对账覆盖平台计价。

费用查看、预算维护、导出与凭据管理分别授权。费用结算不以作品是否完成归档或可预览为判断依据。

08权限与工程规范

复用框架 Authorization Bearer JWT、Redis 会话、菜单按钮与管理数据权限；Service 对项目和对象执行二次鉴权，覆盖搜索、详情、下载、预览、引用和跨项目复制。

  • 授权变更需使用户/权限缓存失效，长连接重验；任务快照固定历史输入，但不提供永久访问授权。
  • 浏览器只能经平台授权入口访问文件，路径由服务端生成；密钥、登录令牌不进入 URL、队列载荷或日志。
  • 所有新增 ORM 使用 AsyncSession；DAO 处理数据库操作，Service 管理事务；并发任务不得共享同一个 Session。
  • 制作端采用 TypeScript 与 <script setup lang="ts">，组件不直接发请求；业务表单复用框架校验和显式操作流程。
  • 亮暗主题共享布局和语义色变量，Element Plus 与 shadcn-vue 统一主题状态；切换保留筛选、选择和未提交输入，媒体原图不反色。

接口继续使用若依响应信封、分页与业务错误约定。制作端和管理端的路由拆分只是组织边界，不能代替服务端鉴权。

09部署、容量与运维

正式部署基线：公司内网服务器运行平台，公司 NAS 长期保存素材及输出；模型调用通过受控出站访问外部供应商。生产操作系统、容器化方式、服务器数量、域名及 NAS 协议/挂载路径由运维确认。

本地开发仅通过 Docker 启动 PostgreSQL 与 Redis；后端、管理端、制作端及需要运行的 Worker 在宿主机分别启动。本地运行方式不直接推导生产部署方式。

扩展与容量

按 generation、polling、media 队列隔离长短任务。API、生成 Worker、媒体 Worker 按瓶颈独立扩容；供应商账号并发与额度独立限流，增加 Worker 不提高采购额度。容量按每日输入、输出、衍生文件、保留期、版本增长及备份系数估算。单机起步不宣称高可用。

发布与恢复

数据库、NAS 文件及解密主密钥分别备份、受控保管，并以同一恢复计划核对。验证文件大小、哈希、引用关系与密钥可恢复性；NAS 快照不能单独替代完整备份。迁移优先兼容新增，破坏性变更先暂停受影响写入并排空任务；API、Worker 和事件 schema 保持兼容。

恢复后默认关闭真实供应商提交，先核对在途任务和上游状态，防止从备份重放已经消费的生成请求。生产联验覆盖 NAS 断连重挂、原子改名、并发归档、视频 Range 播放及外部素材交换。
