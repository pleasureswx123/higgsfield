## 2 已确认的产品范围

### 2.1 必须实现的主流程

生成或上传图片 → 挑选素材 → 建立角色、场景、道具元素 → 在提示词中通过 @ 引用 → 生成视频片段 → 图片与视频长期归档到 NAS。

同时支持直接选择图片生成视频，不要求所有图片都先成为元素。图片和视频生成结果均可在项目素材库中组织、查看和后续复用。

| 事项 | 本平台要求 | 来源和边界 |
|---|---|---|
| 生图 | 文字或参考图片输入，选择模型、参数，生成图片素材 | 用户确认；已查看原站创作控件，未提交扣费生成 |
| 元素资产 | 角色、场景、道具；一个角色可关联多张图片 | 用户确认；已实际打开三图元素并切换预览，见第 10 节 |
| @ 引用 | 选择实际资产，展示引用标识及参考缩略图，结合提示词生成 | 用户确认；Use 回填标签与缩略图已实测，供应商输入映射仍待验证 |
| NAS | 资产图片及生成视频长期保存到公司 NAS，平台授权预览和下载 | 用户确认；不是对原站存储架构的推断 |
| 视频范围 | 生成、保存、预览、下载视频片段 | 用户明确不需要剪辑和拼接 |
| 角色权限 | 配置统一放后台管理平台；制作端按权限开放操作 | 用户确认；项目对象权限仍由后端校验 |
| Tools | Canvas、Chat、AI Director 首期暂不做，隐藏整个分组 | 用户确认；不放不可用占位按钮 |
| 双主题 | 同一结构支持亮色和暗黑，可见切换入口，保留页面与输入 | 项目 AGENTS.md 强制约束；不代表原站双主题已验证 |

### 2.2 素材与元素的区别

素材是具体图片、视频及其来源信息；元素是具有分类、名称、引用标识和关联图片的可复用资产。项目文件夹用于组织素材，Elements 用于管理可引用资产。名为 ASSETS、PROPS 的普通文件夹，不自动等同于元素库或道具分类。

在我的元素内提供制作资产的便捷路径是用户需求；但本次实查的新建元素表单没有直接调用生图模型的按钮。原站已打开的入口路径是“新建元素 → 添加媒体 → Generations”，当前生成列表为空，未完成结果选中保存。本平台新增直接生图入口时必须标记为需求适配，不能称作原站已验证交互。

## 4 文件夹管理：真实操作规则

用户明确授权在测试项目中新建、移动、复制、删除测试目录。此处指第 4 节目录测试；后续第 10 节另有元素创建与恢复。未上传素材或发起生成，本地业务代码和数据库未修改。

| 编号 | 入口/动作 | 已验证行为 | 实现验收要点 |
|---|---|---|---|
| F01 | 侧栏顶部 Add folder | 即使当前打开子目录，也创建项目根目录文件夹 | 不能误放到当前选中目录；创建后不强制切换当前内容页 |
| F02 | 文件夹行 + | 在该目录下创建子目录，父节点自动展开 | 层级、缩进、展开状态正确 |
| F03 | 新建表单 | 名称、可展开描述、颜色；空名称时 Create 禁用 | 保留字段、禁用和提交中状态 |
| F04 | 颜色 | Lime、Cyan、Slate、Violet、Purple、Pink、Yellow 共 7 项 | 图标颜色与选择一致；双主题下可辨认 |
| F05 | Edit | 可修改名称、描述、颜色；保存中控件禁用 | 保存成功后目录树与面包屑同步 |
| F06 | 改名 | URL 中的文件夹 ID 不变 | 标识稳定，不用名称作为持久主键 |
| F07 | Move to | 目标项目/文件夹树，可搜索、排序，并在目标树内新建目录 | 本次从测试父目录移到 test1 成功；原目录 ID 不变 |
| F08 | Copy to | 使用类似目标树，复制后保留原目录，新目录名为 Copy of 原名称 | 本次成功复制空目录至项目根部；有内容递归复制待核实 |
| F09 | Delete | 弹窗说明空目录将移入 Trash，可恢复 30 天 | 二次确认，不直接物理删除 |
| F10 | 删除当前目录 | 左树移除，回收站计数增加，自动返回项目素材页 | 不留失效的当前目录视图 |
| F11 | Restore | 选择条目后支持行内/批量恢复；恢复回原父目录，保留原 ID | 本次恢复到 test1，回收站计数恢复原值 |
| F12 | 搜索目录 | 输入名称后结果平铺；当前内容和面包屑不切换 | 关闭搜索后恢复完整目录树 |
| F13 | 排序菜单 | First created、Last created、Last changed、Name A-Z、Name Z-A | 菜单已打开，实际排序和偏好持久化尚未逐项验证 |
| F14 | 更多菜单 | Open in new tab、Pin、Edit、Color、Add folder、Move to、Copy to、Copy link、Delete | 各入口必须可追踪；置顶、新标签和复制链接本次只确认菜单存在 |
| F15 | 回收站分类 | All、Generations、Elements、Uploads、Folders | 本次仅文件夹恢复通过；其他类型待验证 |

### 5.2 导入元素

Import 弹窗说明支持剧本或表格，提取角色、场景、道具供用户检查，确认复核前不会添加。可选文件后缀为 .pdf、.xlsx、.csv、.docx、.txt、.md，默认勾选“在元素 ID 中包含项目名称”。

这已经超出“只能上传图片”的理解，但只核实了界面说明。尚未提交文件，不能断言实际采用何种 AI、提取规则、费用或准确率。复刻需包含“导入 → 预览复核 → 确认添加”的交互边界，具体实现契约待补齐。

### 5.3 状态和展示

实际点击 Drafts 后，自动筛选 No status、In progress、Needs review。筛选菜单还存在 Approved、Rejected。用户截图中 Active 对应 Approved，后续已实测 Approved 元素出现在 Active；其他状态迁移约束尚未完整验证，见第 10 节。

View 提供 Grid、Board、Table，分组提供 None、Created date、Name，并有卡片大小和图片填充选项。展示布局不应产生新的素材文件。

### 5.4 创作与结果复用

首页和项目内共享图片/视频创作模式。已观察到提示词、模型、比例、分辨率、数量等基础控件；视频还展示时长、声音、参考素材等。当前 Cinema Studio 4.0 的影片设置、摄影机、调色板、灯光等专用控件只能在模型支持时开放，不能把界面预设等同于供应商独立能力。
