# 制作协作流程与验收

本文说明本次实现的制作交接规则。依据当前源码、自动化回归与隔离项目浏览器验收，不以旧设计文档作为功能证明。验证范围与环境边界列在文末。

## 1. 先区分三种对象

| 对象 | 用途 | 版本和状态的含义 |
| --- | --- | --- |
| 素材 | 一份图片或视频内容 | 上传新版本仍属于同一素材；审核针对具体素材版本 |
| 元素 | 可复用的角色、场景、道具等定义 | 一次修订保存描述、属性及固定素材版本引用；元素审核确认这一整套定义 |
| 生成任务 | 按输入和模型生成内容 | 执行成功不等于素材审核通过；任务执行状态与制作状态分开 |

元素中的多张图片是参考内容集合，可以有主图，不代表每张都是元素的一个历史版本。元素修订与素材版本是两层关系。素材上传 V2 不会自动替换元素已选的 V1；修改元素引用并保存，才会产生新的元素修订。

素材通过不自动使元素通过，元素通过也不自动批准其引用素材。当前规则允许元素选用可读取、文件已就绪的素材，不强制所有参考图先单独审核通过。

## 2. 人员怎样分工

项目所有者管理成员和项目权限。负责人组织制作、分配具体内容，并在获得项目审核权限时审核。制作人处理自己负责的内容。查看者按授权查看和下载，不因为有系统级按钮权限就获得项目写入权限。

以上是默认职责说明，实际能力取决于当前项目权限与系统权限。成员名称不是角色；项目角色也不等于某一份内容的制作人。

- 有项目范围编辑权的人可以分配制作人，候选必须是有效项目成员且具有相应编辑权。
- 内容未显式分配时以创建人为制作责任人；显式分配后按分配人员判断本人编辑范围。
- 分配只授予对应制作职责，不隐式授予删除或审核权限。
- “审核通过与退回”使用项目范围授权；旧的本人范围审核配置不会被升级为项目审核权。
- 当前未强制制作人与审核人必须不同；具有明确审核授权的人可审核自己制作的内容。

## 3. 从制作到通过

| 当前状态 | 操作 | 结果与要求 |
| --- | --- | --- |
| 未开始 | 开始制作 | 进入制作中 |
| 制作中 | 提交审核 | 进入待审核；提交当前版本，文件必须就绪，元素必须包含可用参考素材 |
| 待审核 | 撤回 | 返回制作中 |
| 待审核 | 退回修改 | 进入待修改；审核人必须填写具体修改意见 |
| 待修改 | 开始制作 | 返回制作中，处理反馈后重新提交 |
| 待审核 | 审核通过 | 记录具体版本的通过证据 |
| 已通过 | 重新制作 | 返回制作中，保留旧审核记录 |

待审核、已通过或待修改的内容产生新版本时，当前状态回到制作中，需要重新提交。查看旧版本不能操作当前版本审核。过期页面提交会被修订校验拒绝，需要刷新后核对。

推荐操作顺序：

1. 负责人在内容描述中明确要求，分配制作人。
2. 制作人上传或生成素材；需要统一角色、场景等定义时整理为元素。
3. 保存修改后提交审核，不能拿未保存的描述提交。
4. 审核人查看具体版本，直接通过，或者填写可执行意见退回。
5. 制作人按照意见修改，保存新版本并重新提交。
6. 审核人确认新版本，通过后用于后续创作或下载。

## 4. 评论和标注如何参与

评论与画布标注用于说明某个具体素材版本的问题。普通交流可以独立于审核发生；解决讨论只代表这条讨论被处理，不等于整份内容通过。

审核退回理由保存在流转记录中。评论和标注提供细节，不能代替明确的退回或通过动作。V2 的评论、标注不出现在 V1；旧版记录保留，不随新版本覆盖。

退回意见草稿在当前登录会话内按对象和版本隔离，关闭后重新打开同一内容可恢复。该能力不承诺跨浏览器刷新持久保存。请求结果不明时，重试沿用原操作标识，避免重复流转。

## 5. 导入和引用

导入流程是：上传清单、解析候选、人工复核、确认创建元素。它不会替用户生成媒体，也不会自动完成审核。导入后的空图元素可以保存，但必须补充可用参考素材才能提交审核。

创作栏的 `@` 按钮与输入框键入 `@` 都可选择元素。选中后写入元素修订及素材版本的结构化引用；正式提交时服务端重新校验权限、项目归属、媒体就绪状态及版本对应关系。

最终采用内容应通过具体版本识别，不能只看名称或当前状态。新版本重新制作时，旧版通过证据仍存在，但不代表新版本已经通过。

在素材详情或元素编辑器展开“流转记录”，点击“查看此版本”可直接查看该次提交、退回或通过对应的内容。元素历史窗口只读展示该修订的分类、描述、属性和固定媒体，不替换当前编辑草稿。素材历史预览提供“查看最新版本”返回入口。旧记录未绑定版本时不提供猜测的跳转。

## 6. 已取得的验收证据

隔离项目为“制作协作闭环验收-1111”，使用合成蓝色 V1、橙色 V2 图片。未调用付费生成。

- 所有者分配后，制作人提交，负责人退回；制作人上传 V2 后重新提交，负责人通过。
- 元素补充描述后重新提交并通过；素材已经更新到橙色 V2，元素仍引用蓝色 V1。
- 查看者可读、可下载，不能制作、审核或发表评论；下载内容哈希与上传 V2 一致。
- 普通评论标记已解决后素材仍保持原审核状态；V2 标注未出现在 V1。
- 导入清单创建了无图元素；无图提交被拒绝，提示先补参考素材。
- 浏览器实际选择工具栏元素入口及输入框 `@`，两者均写入参考素材版本 38；缺图元素不可选择。
- 前端生产构建通过；最新制作面板、元素编辑会话与评论回归 60 项通过。
- 最新后端状态、审核证据、权限、历史预览与引用回归共运行 39 项，其中 35 项通过、4 项数据库用例因未启用而跳过。跳过不计为通过。
- 另行显式启用真实 PostgreSQL 制作闭环集成测试，1 项通过：在独立事务中验证素材与元素转交后旧制作人直接请求被拒绝；保留元素分配、将制作人降为查看者后，下一次提交也被拒绝。测试最终回滚，不改变现有项目。
- 浏览器从元素退回记录打开修订 #1，显示“蓝色制服，第一版角色设定。”；关闭历史窗口后当前第二版描述保留。素材退回记录直接打开蓝色 V1，地址定位版本 38，审核操作禁用。

## 7. 最终检查与验收边界

本地导入验收时没有正在运行的导入工作器，测试批次通过调用现有工作器处理指定批次后完成；不能据此宣称自动后台消费已验收。

最终变更集合完成了以下检查：

| 要求 | 实现与证据 |
| --- | --- |
| 两类内容共用动作规则，禁止任意跳级 | `production_workflow.py`、旧状态入口拒绝测试、浏览器提交与退回 |
| 审核固定版本，保留历史而不伪造旧证据 | 真实迁移92/93、审核DAO、迁移与服务集成测试 |
| 分配、制作与审核权限分离 | 制作责任范围测试、项目审核范围测试、查看者浏览器只读验收 |
| 转交或撤权后旧操作被拒绝 | 真实数据库集成测试；系统通配权限也不能绕过项目范围 |
| 旧页面、重复请求不覆盖审核 | 修订冲突与幂等重放集成测试；第二个旧客户端的新操作键被拒绝且没有多写审核记录 |
| 评论、标注不替代审核且按版本隔离 | 浏览器V2创建/解决评论、绘制标注，V1无这些记录；评论权限回归 |
| 元素固定引用、导入不等于制作完成 | 两种 `@` 入口浏览器验收，导入创建后无图提交拒绝 |
| 历史内容可查、最终版本可访问 | 元素修订 #1 定向打开；素材版本38返回已通过版本41；实际下载哈希核对 |
| 保留草稿和未确认操作，避免迟到响应污染 | 制作、评论、编辑器和历史窗口会话测试 |
| 双主题与浮层稳定 | 亮暗主题截图、窄屏元素编辑检查、两主题表格边界对照 |

最新前端相关回归64项通过；最新后端相关回归34项通过（包含显式启用的真实迁移、数据库闭环）。数据库闭环随后扩充了旧修订冲突和移出成员访问拒绝断言，单独复跑1项通过。类型检查及生产构建通过；构建仍有既有大分包提示。

权限转交和角色撤销使用服务集成证据，不表述为对应浏览器操作验收。并发编辑检查覆盖旧客户端修订冲突，不表述为压力或吞吐测试。历史视频类型分支经过回归，浏览器历史查看使用合成图片验证。

## 8. 2026-11-11 再次复查与修复

本轮重新检查实际操作链路，发现并修复以下问题：

- 制作信息刷新失败后清除旧状态及可用动作，成功重读前不能继续提交；系统权限变化重新读取授权，退出登录后停止读取并清空会话状态。
- 制作人列表加载与审核状态读取分离。成员读取失败时明确提示刷新，禁止使用旧候选分配，但不阻塞已经获得授权的审核操作。
- 制作人候选按素材、元素各自的实际编辑权限筛选，不按角色名称判断。默认查看者不具备制作权限；项目明确授予编辑权限后，候选与后端授权保持一致。
- 退回修改意见直接显示在制作操作区，开始返工后继续保留；上一轮已经通过的意见不作为新一轮待处理意见。
- 小文件按 B、KB、MB、GB 显示，避免有效文件显示为 `0.0 MB`。

前端制作面板、元素编辑及历史会话、评论和组件绑定回归共 69 项通过。类型检查与生产构建通过，仍有既有大分包及静态/动态导入提示。

后端制作人分配权限、制作审核服务、审核权限范围及真实 PostgreSQL 闭环回归共 14 项通过，显式启用数据库用例，无跳过；数据库测试使用事务回滚，不改变现有业务数据。

浏览器使用隔离项目的合成素材重新走通“重新制作 → 提交审核 → 退回修改 → 开始返工 → 再次提交 → 审核通过”，检查亮暗主题中的意见可读性、制作人单选后自动收起及 `3.3 KB` 文件大小显示，最终将测试素材恢复为已通过。截图保存在本地忽略目录 `output/ui-audit-workflow/`：`recheck-feedback-light.png`、`recheck-feedback-dark.png`、`recheck-approved.png`。前两张在文件大小修复前拍摄，最终文件大小以最后一张为准。
