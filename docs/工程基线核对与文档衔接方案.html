4 协议衔接

框架原生接口（/login、/getInfo、/system/*、/monitor/*等）维持原路径和原响应。管理端继续使用原请求器；新业务接口固定 /api/v1 与 /api/admin/v1，由遵循框架响应码的统一请求适配处理 DTO、Decimal 字符串、页码分页与幂等。反向代理保留业务/api前缀，不把它按/dev-api的规则剥掉；原框架开发代理继续按现有配置工作。

P0-4中曾列出的/users、/roles、/departments等身份管理门面改为后续可选适配，首期默认复用原生系统页面和API，避免维护两套用户角色写路径。/api/v1/me仍是供制作端使用的新增归一读取视图。新业务权限码登记到框架菜单/权限体系，项目范围由独立策略强制检查；即使功能权限含通配符也不能跳过对象范围。

Bearer鉴权下SSE采用fetch流式读取，携带Authorization和Last-Event-ID，不使用无法附加该头的原生EventSource。文件下载用授权fetch；视频Range/媒体播放器需要支持附加鉴权头的加载层，不能直接把受保护URL放进video标签后假定自动带Bearer，不能把token放query。后台上传、SSE和Range流需与传输加密中间件协作：核对实际启用/排除策略，禁止把二进制或事件流当普通JSON加密，传输加密也不能代替HTTPS。

两个前端使用同一用户目录与登录后端，但“同一后端”不等于已实现自动单点登录。首期各自维护受控会话，制作端默认内存持有token；是否跨刷新保留、是否启用OIDC统一认证需另行评审。框架的同账号多终端登录配置也需联调，不能承诺登录另一端必定不踢出原会话。

8 前端选型与强制编码规范（已确认）

管理端使用 ruoyi-fastapi-frontend/vue3/web/ 的 Vue3 工程；本地 package.json 已声明 vue、pinia、element-plus，不切换至父目录中的 Vue2/React 版本。制作端 higgsfield-frontend/ 使用 Vue3、TypeScript，Element Plus 与 shadcn-vue 共存，按实际场景选择组件。

制作端全部业务组件使用 <script setup lang="ts">，使用组合式 API；use 开头的 composables 承载业务逻辑；API 请求集中独立模块；组件单一职责；共享状态使用 Pinia，不使用 Vuex；命名、导出、ref/reactive/computed 按统一组合式规范执行。

新增制作平台前端编码规范及制作端 AGENTS.md，明确模块职责、组件库共存和评审要求。当前只是规范落盘，未安装依赖、创建业务组件或配置 lint/typecheck 门禁。两套前端手动启动、共享后端和 Docker 基础设施的本地开发方式保持既定约定。

前端统一编码约束（补充确认）： 两端新增及修改的前端业务代码使用 Vue3 + Vue Router + Pinia + Axios，统一 <script setup>，禁止 Options API；业务逻辑放 use 开头的 composables，请求放 api/ 独立模块，路由定义和守卫由 Vue Router 管理，全局状态由 Pinia 管理。代码风格遵循制作平台前端编码规范中的明确约定。保留管理端存量工程；本次未重写已有组件或初始化制作端。

制作端双向绑定约束： higgsfield-frontend 使用 Vue3.4+，自定义组件双向绑定优先 defineModel()，支持多个 v-model:xxx；禁止 .sync，子组件严禁直接修改 props（包括嵌套对象/数组）。详见制作平台前端编码规范第9章。数据库继续执行已确认的若依统一规范，无物理外键。
