# AI图片与视频制作平台建设方案

版本：1.0  
日期：2026年10月27日  
读者：公司管理层、业务负责人  
用途：说明建设目标、交付范围及决策事项。本文是方案说明，不是上线或验收报告。

## 一、我们要建设什么

建设一个供公司内部使用的AI图片与视频制作平台，把“准备角色和场景、生成图片、生成视频、保存成果、管理费用”放在同一个工作流程里。

员工在制作平台中工作，管理员在后台管理人员权限、供应商账号、可用模型和预算。图片与视频长期保存在公司NAS中，项目记录、素材关联和使用费用由平台统一管理。

界面和创作操作参考Higgsfield；实际生成使用公司采购供应商的模型。我们建设的是制作和管理平台，首期不自研或训练图片、视频大模型。

## 二、员工怎样使用

以制作一段“女孩在海边转身”的视频为例：

1. **进入项目。** 项目用于组织成员、素材、生成结果和费用。
2. **准备资产。** 在“我的元素”中建立女孩角色、海边场景等条目，通过生图模型生成图片，或上传已有图片。一个角色可以保存正面、侧面等多张图。
3. **挑选图片。** 将满意的图片加入对应角色或场景，作为以后可以重复使用的资产。
4. **生成视频。** 在提示词中选择“@女孩”和“@海边”，描述“女孩缓缓转身，镜头向前推进”，选择视频模型和参数后提交。
5. **查看与归档。** 平台展示任务进度，将生成图片和视频保存到NAS，支持查看、下载、评论及后续复用。

也可以直接上传或选择图片生成视频，不要求每张图片都先建立为元素。元素的价值是整理和复用角色、场景、道具；它有助于提供一致的参考，但不能保证不同模型每次都生成完全一致的人物。

## 三、首期交付哪些功能

| 业务部分 | 交付内容 | 使用价值 |
|---|---|---|
| 项目与素材组织 | 项目、成员、文件夹、搜索筛选、删除恢复 | 按项目管理创作资料，减少散落文件 |
| 角色、场景、道具 | 多图元素、主图、分类、属性、状态、导入复核 | 为重复创作建立可复用的资产 |
| 图片与视频生成 | 供应商模型选择、提示词、图片引用、参数、任务进度 | 在同一入口完成图片到视频的制作 |
| 成果与协作 | 结果详情、来源追溯、评论、图片标注、NAS归档 | 能找到成果，也能查清它如何生成 |
| 后台管理 | 人员权限、供应商密钥、模型配置、价格、预算及用量 | 控制谁能使用、能花多少、费用归哪个项目 |

首期暂不建设公司公共素材库、Canvas画布、Chat聊天、AI Director导演工作流、社区、外部分享及商业订阅。语音和独立文本聊天产品也不在首期范围。项目内部的素材使用与协作正常保留。

模型目录有20个供应商调用名称，但不等于20项能力都能立即上线。图片、视频模型按实际接口验证后逐项开放；4K、Fast、声音、首尾帧和摄影机等参数，必须由对应模型支持才能提供。

## 四、平台怎样支撑业务

```text
员工制作页面                  管理员后台
    │                            │
    └──────── 公司平台服务 ────────┘
                 │
        ┌────────┼─────────┐
        │        │         │
      项目记录  公司NAS   外部模型供应商
      用量费用  图片视频   执行图片/视频生成
```

平台部署在公司内网，媒体文件长期归档到NAS。员工通过平台授权访问文件，不直接操作NAS共享路径。

生成仍需要调用外部供应商，因此“内网部署”不等于素材始终不出内网。提交模型所需的提示词和参考素材，会按接口要求受控发送；应由公司明确哪些内容允许用于外部生成。供应商不会因此获得整个NAS的访问权。

## 五、费用如何管理

生成前展示可用的费用估算并检查预算，受理任务时先预占预计额度；获得供应商实际用量后，再按任务固定的价格规则计算，后续可与账单核对。预占是平台内部额度控制，不等于当时已向供应商付款。

平台区分内部使用计价和供应商采购成本，两者不是默认相同的一笔金额。缺少用量时显示“待确认”，不能当成免费。最终采购支出以供应商计费依据和账单核对结果为准。

目前没有足够依据承诺“每条视频固定多少钱”或“每月可以节省多少费用”。应在试点中记录生成次数、成功率、实际费用、人工挑选时间与返工情况，再评估投入产出。

## 六、怎样分步交付

| 阶段 | 应看到的实际结果 | 验收重点 |
|---|---|---|
| B1 管理基础 | 能登录、建项目、配置成员与模型预算 | 权限与供应商配置可控 |
| B2 图片闭环 | 能生成图片、跟踪任务、保存到NAS并记录费用 | 不重复提交、不丢结果、费用可追溯 |
| B3 视频闭环 | 能把角色多图通过@引用用于视频生成 | 资产到视频全流程打通，异常能恢复 |
| B4 协作与试点 | 文件组织、评论标注、用量统计及对账可用 | 在真实项目中验证可用性与管理效果 |

B2可以用于阶段演示，但不能代表整个首期已经完成。排期需要结合人员投入、现有代码核实、供应商联调和NAS环境确认后制定，本文不预设未经评估的日期或人天。

## 七、主要不确定因素与处理方式

| 不确定因素 | 处理方式 |
|---|---|
| 模型效果、接口参数和账号能力可能不同 | 先验证拟开放模型，再开放给员工；保留模型版本与生成参数 |
| 网络超时，不知道供应商是否已接单 | 保留任务核查，不能直接重发付费生成 |
| 生成成功但NAS保存失败 | 显示归档异常并重试保存，不通过重新生成来掩盖问题 |
| 费用或用量返回不完整 | 保持待确认状态，保留原始证据并对账 |
| 员工离开项目或权限变化 | 新操作重新校验权限，历史任务与费用记录保留 |

## 八、推进前需要落实的事项

- **试点业务与负责人：** 选择哪个项目、由谁评价生成效果和实际可用性。
- **人员与优先级：** 明确产品、开发、测试和运维投入，再制定交付时间。
- **预算规则：** 确认试点消费额度、费用查看范围以及超额处理方式。
- **素材出站范围：** 明确哪些角色、场景图片和提示词可以提交给外部供应商。
- **基础环境：** 运维确认内网服务器、NAS访问方式、容量、备份和外部接口连接条件。

目前已形成界面与功能基线、供应商目录及配套设计文档。文档完成不代表全部功能已实现，也不代表真实模型调用、费用或NAS归档已经验收。下一步应以分阶段演示和真实项目验收判断进度。
