# 内网部署与 NAS 存储方案

更新于 2026-11-24。正式环境已上线，服务状态、挂载和备份操作见[内网正式环境](../deploy/intranet/README.md)。

## 目标

公司内网服务器运行管理端、制作端、共享API与后台工作器；PostgreSQL保存元数据和账本，Redis承载框架会话/缓存；媒体长期保存公司NAS。浏览器通过平台授权读写，供应商通过后台受控接口交互。

## 当前与正式环境区别

本机开发环境使用 NAS 的 NightmareTheatre/dev 目录。独立自动化测试仍可使用 local-test 临时目录。正式后端和工作器通过服务器的 CIFS 挂载访问 NightmareTheatre/prod。页面没有已实现的通用NAS路径设置向导；挂载、服务账户和网络由部署维护人员完成，可由平台管理员协调，不需要新增业务角色。

## 开发环境的项目目录

项目和制作平台的多级文件夹位于 `\\192.168.1.13\Project\NightmareTheatre\dev`。平台提交操作后，后端约每 5 秒检查一次目录变化。项目首次分配的目录名保持稳定。素材显示当前版本，文件夹内同名文件自动编号，扩展名取自已验证的媒体类型。归档文件、暂存分片和加密证据使用独立的内部目录。

平台的存储键保持稳定。项目文件是 NAS 内部媒体的硬链接，预览和下载继续通过原有授权接口。制作人员在平台里改名、移动、复制或回收；NAS 浏览用户只应有读取权限，对硬链接写入会改变平台原文件。内部目录和清单仅授权服务账号管理；开发与正式根目录和权限应分别配置。同步保留用户自行放入的其他文件。

启用同步需设置 `HF_NAS_PROJECT_DIRECTORIES=1`、`HF_STORAGE_MODE=nas`、`HF_NAS_SOURCE` 和 `HF_STORAGE_ROOT`。存储根目录指向同卷的 `<环境>/.platform`。Windows 使用 UNC 路径，Linux 使用已核验的挂载目录。所有 API 和工作器须使用同一环境配置。切换已有数据时，暂停写入并对照数据库核验复制文件的大小及 SHA-256，再启动服务。NAS 目录同步异常会记入后端日志并自动重试。

## 上线确认清单

- 操作系统、部署方式、服务器数量、反向代理和HTTPS。
- NAS协议、挂载路径、服务账户读写权限、容量、断挂检测和恢复。
- PostgreSQL与媒体一致性备份、恢复演练，账本及审计留存。
- 密钥配置、受控出网、日志脱敏、临时URL过期处置。
- 工作器托管与重启、积压/心跳/归档失败/待计价监控。
- 数据库迁移、应用版本与回滚方案。

禁止NAS不可用时无提示地写到另一块本地目录；不能把供应商临时URL当长期文件。不得从本地Docker方式推断正式容器化方案。
